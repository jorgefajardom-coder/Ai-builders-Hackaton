# ADR-004 — Railway siempre encendido, una réplica, healthcheck por Host

## Contexto
El entrypoint debe estar accesible desde internet **desde las 20:00 hasta el final del demo day**, con `GET /health` y el token del equipo. El estado vive en memoria ([[ADR-002]]), así que necesitamos exactamente una instancia, sin cold starts ni suspensión por inactividad.

Railway verifica el healthcheck **solo durante el deploy**: lo llama **sin token**, desde el host `healthcheck.railway.app`, y exige un 2xx. Pero el original responde `401 E001` a `/health` sin token (log #2), y el reemplazo debe responder igual. Si el healthcheck se configura sin más, el deploy falla.

## Decisión
- **Railway**, con `numReplicas: 1` y **Serverless apagado**, configurado en `railway.json`. Uvicorn con `--workers 1`.
- **Healthcheck:** `GET /health` responde `200 {"ok":true}` sin token **solo si** `Host == healthcheck.railway.app`. Con cualquier otro Host se aplica el comportamiento del original (`401 E001` sin token).
- Secretos (`TEAM_TOKEN`) en las variables de entorno de Railway.

## Alternativas descartadas
| Alternativa | Por qué la descartamos |
|---|---|
| Agregar `/healthz` sin auth | Toda ruta extra rompe la paridad: en el original debe dar `404 E404` |
| No configurar el healthcheck | Railway no sabría cuándo está listo cada deploy; un deploy roto quedaría activo sin aviso |
| `/health` sin token siempre 200 | Rompe la paridad con el original (`401 E001`, log #2) |
| Serverless de Railway / Lambda / Cloud Run escalando a 0 | El estado en memoria no sobrevive y el primer request al despertar puede dar 502 |
| Render o Fly.io | Render gratis se duerme (cold start contra el límite de 5 s); Fly pide más configuración sin ganancia frente a Railway, donde ya corre el original |

## Consecuencias
- **Ganamos:** deploys verificados automáticamente sin tocar la paridad. El jurado nunca usa ese Host.
- **Riesgo:** un cliente podría falsificar el header `Host` para obtener el 200. Se acepta: la respuesta no expone nada (`{"ok":true}`). Va documentado en *Riesgos* de la spec.
- **Desplegar temprano** (antes de las 13:00 un esqueleto con `/health`) para descubrir problemas del proxy.
- Después de cada deploy, smoke test contra la URL pública **con** el token del equipo, y el tester diferencial también contra la URL desplegada.
