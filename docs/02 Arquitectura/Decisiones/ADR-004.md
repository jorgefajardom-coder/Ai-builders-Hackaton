# ADR-004 — Hosting siempre encendido, una instancia

## Contexto
El entrypoint debe estar accesible desde internet **desde las 20:00 hasta el final del demo day**, con `GET /health` y el token del equipo. El estado vive en memoria ([[ADR-002]]), así que necesitamos exactamente una instancia, sin cold starts ni suspensión por inactividad.

## Decisión
**Por decidir.** Criterios: siempre encendido, 1 instancia fija, secretos por variable de entorno, deploy desde git en minutos, HTTPS incluido y **que no inyecte respuestas propias** (páginas de error del proxy, redirects).

| Opción | A favor | En contra |
|---|---|---|
| Fly.io | Máquina persistente, `min_machines_running=1`, control de instancias | Requiere tarjeta; configurar `fly.toml` |
| Railway | Deploy desde GitHub muy rápido, siempre encendido | Plan de pago para uptime garantizado |
| Render (pago) | Simple | El plan gratis se duerme → cold start = fallos en el set oculto |
| VM propia (EC2/DO) | Control total | Más setup (TLS, proceso, reinicios) |

## Alternativas descartadas
| Alternativa | Por qué la descartamos |
|---|---|
| Serverless (Lambda, Cloud Run escalado a 0, Vercel functions) | El estado en memoria no sobrevive entre invocaciones y puede haber varias instancias en paralelo |
| Plan gratis con suspensión | Cold starts y riesgo de que la primera llamada del evaluador falle |

## Consecuencias
- **Desplegar temprano** (antes de las 13:00 un esqueleto con `/health`) para descubrir problemas del proxy del hosting.
- El tester diferencial debe correr también contra la URL desplegada, no solo contra local.
